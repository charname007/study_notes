# ConVIRT：把 CLIP 那套搬到胸片-报告上，早于 CLIP

> Yuhao Zhang 等（微软研究院 + 英属哥伦比亚大学）。页码指本机 PDF 页码。

## 一句话总结

用**胸片和放射报告**做双向对比学习：一个 batch 里，胸部 X 光图要认出自己的报告，报告也要认出自己的图（p.6 的方法描述）。学到的图像编码器在少量标注下做分类和分割，显著优于从头训练和 ImageNet 预训练。**它比 CLIP 更早**，是「自然配对的专业语料也能做对比对齐」这一判断的第一个有力证据。

## 要点提炼（速览）

1. **双向损失**：图像侧和文本侧各有编码器 + 投影头，都投影到同一 $d$ 维空间（p.6），然后两个方向各算一次对比。这个「双向」结构和后来的 CLIP 完全一致。

2. **增广是专门设计的**：医学图像不能用随机裁剪/颜色抖动那套（会破坏诊断信息）。作者对图像用随机裁剪 + 仿射 + 色彩抖动（幅度受限），对文本用**句子级打乱与采样**——因为一份报告里不同句子描述不同发现。

3. **核心结论**：在分类和分割任务上，用极少标签做线性探针或微调时，ConVIRT 预训练显著优于 ImageNet 预训练和随机初始化。

4. **它证明了「配对语料」比「标注语料」便宜得多**：放射报告是临床流程的自然产物，不需要额外标注成本。

## 为什么值得从多模态对齐的角度读

它是 [[CLIP 大规模图文对比预训练]] 的**方法论前身**（时间上更早，但影响力小得多）。差别在于：CLIP 用 4 亿网络噪声数据换通用性，ConVIRT 用几万专业配对数据换领域专精。

这提示一件重要的事：**对比对齐的成败不只取决于损失和规模，更取决于「配对信号里有多少真信息」**。网络图文对的噪声是「部分描述」，医学报告的噪声是「报告里只有部分句子对应这张图」——两者是同一类问题。

## 局限

- 领域性强，方法本身没有超出双向对比 + 编码器的通用框架，创新主要在「怎么把增广改得适合医学数据」。

- 数据规模小（万级），没有验证「专业语料堆到亿级会怎样」。

- 评测集中在分类/分割的标签效率上，没有系统评估跨模态检索本身的质量。
