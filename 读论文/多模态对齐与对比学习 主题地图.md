## 一、损失函数的源头

- ⭐ [[CPC 对比预测编码与 InfoNCE]] — arXiv:1807.03748。InfoNCE 的出厂地，互信息下界，所有对比对齐的数学地基
- ⭐ [[SimCLR 简单框架的四个关键设计]] — arXiv:2002.05709。NT-Xent，消融出「增广组合 > 一切」
- ⭐ [[MoCo 动量对比与队列字典]] — arXiv:1911.05722。队列 + 动量编码器，把负样本数与 batch 解耦
- [[SimSiam 停梯度就够了]] — arXiv:2011.10566。证明不需要负样本、不需要动量，stop-gradient 就够（**未精读**）

## 二、不用负样本的一支

- BYOL (arXiv:2006.07733) — 师生网络 + 预测头，完全不用负样本
- SwAV (arXiv:2006.09882) — 聚类分配 + 多裁剪，用原型代替两两对比
- SimSiam (arXiv:2011.10566) — 把 BYOL 剥到最简，只剩 stop-gradient
- **这一支的意义**：它们说明「推远负样本」不是必需的，「防止坍缩」才是真问题。三种防坍缩手段分别是：负样本（SimCLR）、动量不对称（BYOL/MoCo）、停梯度（SimSiam）。

## 三、视觉-语言对齐的史前史（2013–2020）

- DeViSE (NIPS 2013) — 深度视觉-语义嵌入，最早的图文双塔。**arXiv 上无对应编号，未收录 PDF**
- Kiros 等 2014 (arXiv:1411.2539) — 统一视觉-语义嵌入 + 多模态神经语言模型，双塔 + 排序损失
- Show and Tell (arXiv:1411.4555) — CNN + LSTM 图像描述，生成路线的起点
- Karpathy & Fei-Fei 2014 (arXiv:1412.2306) — 区域-词级细粒度对齐，可解释对齐的早期代表
- VSE++ (arXiv:1707.05612) — 难负样本挖掘，直接把「负样本质量」当成方法
- ConVIRT (arXiv:2010.00747) — 胸片-报告双向对比，医学版 CLIP，证明该范式可迁移到专业领域

## 四、融合式视觉语言预训练

- ViLBERT (arXiv:1908.02265) — 双流 + 跨模态注意力，VLP 的开山之一
- LXMERT (arXiv:1908.07490) — 三路编码器 + 五项预训练任务
- UNITER (arXiv:1909.11740) — 单流统一表征，把 VLP 做成标准范式
- Oscar (arXiv:2004.06165) — 用 object tag 作锚点，让对齐有明确的语义落点
- ViLT (arXiv:2102.03334) — 去掉区域监督，极简 VLP
- ⭐ [[ALBEF 先对齐后融合与动量蒸馏]] — arXiv:2107.07651。明确区分「对齐」与「融合」两步 + 动量蒸馏治噪声标签
- VLMo (arXiv:2111.02358) — Mixture-of-Modality-Experts，用 MoE 统一双流与单流

## 五、CLIP 家族与表示对齐

- ⭐ [[CLIP 大规模图文对比预训练]] — arXiv:2103.00020。4 亿图文对，零样本 ImageNet 76.2%
- ALIGN (arXiv:2102.05918) — 10 亿级噪声图文对，证明数据规模可以压过数据清洗
- LiT (arXiv:2111.07991) — 冻结图像塔只调文本塔，说明瓶颈常在文本侧
- ⭐ [[SigLIP 用 Sigmoid 损失解耦批大小]] — arXiv:2303.15343。sigmoid 逐对损失，32k batch 就够
- SigLIP 2 (arXiv:2502.14786) — 多语言 + 定位/密集特征，把 sigmoid 路线推到 2025
- CLIP4Clip (arXiv:2104.08860) — 把 CLIP 迁到视频检索，系统比较各种时序聚合
- VideoCLIP (arXiv:2109.14084) — 用**时序重叠**构造正样本，直接针对视频-文本的低相关性问题

## 六、对比 + 生成的混合目标

- BLIP (arXiv:2201.12086) — 理解/生成统一，用自举方式过滤噪声图文对
- CoCa (arXiv:2205.01917) — 同一个模型上同时挂对比损失和描述生成损失，两种能力的并集
- **这一支的洞察**：纯对比只能打分不能生成，纯生成又太贵；混合目标试图两头都要。

## 七、接口对齐：接 LLM

- ⭐ [[BLIP-2 用 Q-Former 桥接冻结的图文模型]] — arXiv:2301.12597。32 个查询做信息瓶颈，两端全冻结
- LLaVA / Visual Instruction Tuning (arXiv:2304.08485) — 一个线性投影 + 视觉指令数据，路线最简单也最有效
- Flamingo (arXiv:2204.14198) — Perceiver Resampler + 门控交叉注意力，少样本多模态的标杆
- InternVL (arXiv:2312.14238) — 把视觉塔与 LLM 的对齐规模化
- Qwen2-VL (arXiv:2409.12191) — 任意分辨率 + M-RoPE 的视觉位置编码

## 八、跨模态扩展

- ⭐ [[ImageBind 用图像绑定六种模态]] — arXiv:2305.05665。只靠图像配对，涌现式绑定六模态
- CLAP (arXiv:2206.04769) — 音频-文本对比，把 CLIP 范式搬到听觉
- AudioCLIP (arXiv:2106.13043) — 把音频加进 CLIP 的三模态扩展
- VATT (arXiv:2104.11178) — 视频/音频/文本的自监督 Transformer，用对比学多模态表征

## 九、自监督视觉的旁支（对比学习的近亲）

- SimCLRv2 (arXiv:2006.10029) — 大模型 + 半监督，把对比学习推向实用
- MoCo v2 (arXiv:2003.04297) — 增广 + MLP 头的最小改进，说明 MoCo 的瓶颈不在架构
- SupCon (arXiv:2004.11362) — 有监督对比学习，把标签信息用进对比框架
- DINO (arXiv:2104.14294) — 自蒸馏 + 无标签，ViT 的注意力图自发出现语义分割
- DINOv2 (arXiv:2304.07193) — 把 DINO 做成可用的通用视觉特征，无需微调
- **这一支与多模态的关系**：它们的图像塔经常就是后面 VLM 的视觉主干；理解它们才能理解「冻结的图像塔里到底有什么」。

## 十一、读这批论文时反复出现的三个坑

1. **「对齐」是三种不同的东西**——表示对齐 / 融合对齐 / 接口对齐，指标不可互换。详见 [[多模态对齐的三种含义]]。
2. **batch size 与损失强耦合**——CLIP 的结论建立在 32768 上，小 batch 复现要么换 sigmoid，要么结论不成立。详见 [[对比损失谱系 InfoNCE 到 Sigmoid]]。
3. **模态 gap 常在文本侧**——LiT 的动机就是「冻结图像塔、只调文本塔反而更好」，说明图文对齐的瓶颈往往不在视觉。
