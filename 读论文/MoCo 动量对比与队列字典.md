# MoCo：把字典从 batch 里解耦出来

> Kaiming He, Haoqi Fan, Yuxin Wu, Saining Xie, Ross Girshick（FAIR）。页码指本机 PDF 页码（正文 8 页 + 参考文献）。

## 一句话总结

对比学习的效果取决于**字典有多大、里面的 key 有多一致**。端到端方法被 batch size 卡住，memory bank 被「编码器一直在变」污染；MoCo 用**队列 + 动量编码器**同时满足这两条：字典可做到 65536，且队列里的 key 由一条缓慢演化的编码器产生，一致性有保证。ImageNet 线性分类 **60.6%**，是当时最接近监督预训练的无监督方法，且只需约 1/7 的 GPU 与 1/4 的训练时间。

## 要点提炼（速览）

1. **三种对比机制的本质差别**（p.3, Fig. 2）：(a) 端到端——字典 = 当前 batch，大 batch 才能大字典，受显存所限；(b) memory bank——字典覆盖整个数据集，但**每次只有当前 batch 的表示被更新**，其余是好几轮之前的陈旧值；(c) MoCo——字典是队列，**用动量缓慢更新的编码器来生成 key**，新旧一致。
2. **队列**（p.3）：字典是一个 key 队列，新 batch 入队、最老的出队，原文称其 decouples the dictionary size from the mini-batch size。$K=65536$（p.5）。
3. **动量更新**（p.3）：$\theta_k \leftarrow m\theta_k + (1-m)\theta_q$，$m=0.999$。作者说 $m$ 取大值之所以重要，是因为它让 key 编码器**变化足够慢**，队列里的 key 才不会互相矛盾。消融显示 $m$ 在 0.99–0.9999 之间都工作良好，$m=0.9$ 明显掉点（p.5）。
4. **为什么不直接复制参数**：若 $\theta_k=\theta_q$，队列里不同时刻的 key 就由差异很大的编码器产生，对比退化成在比「不同模型」而非「不同样本」。这是整篇论文最核心的一句动机。
5. **损失**：InfoNCE，温度 $\tau=0.07$。
6. **结果**（p.5–6）：ImageNet-1M 线性分类 **60.6%**，原文称其优于同规模的所有对手；下游检测/分割上，MoCo 预训练在 AP 上甚至**超过** ImageNet 监督预训练的对应设置（如 R50-dilated-C5 AP50 81.1 vs end-to-end 79.2）。
7. **代价很低**：8 卡训 200 epochs，比当时的对比方法省 7× GPU、省 4× 时间（摘要）。

## 核心问题

对比学习要学好，需要**又大又一致**的负样本字典。但当时两种做法各缺一半：

| 机制 | 字典大小 | 一致性 | 卡在哪 |
|---|---|---|---|
| 端到端 | = batch size | 高（同一个编码器） | 显存墙。想 65536 就要 65536 张图同时前向 |
| memory bank | 全数据集 | **低**（陈旧表示） | 表示每轮都在变，bank 里的值早已过期 |
| MoCo | 可任意设 | 高 | — |

所以问题被重述成：**怎么让字典大，同时保证里面的 key 由同一个编码器产生？**

## 关键方法

### 1. 队列代替 bank

用 FIFO 队列存最近 $K$ 个 batch 的 key 表示。队列里的 key 是**渐进替换**的——每来一个新 batch，淘汰最旧的一批。这样字典规模变成超参数（$K=65536$），与显存里能同时放下多少图解耦。

### 2. 动量编码器保证一致性

$$\theta_k \leftarrow m\theta_k + (1-m)\theta_q,\quad m=0.999$$

$\theta_k$ 不做梯度更新，只跟随 $\theta_q$ 指数滑动平均。$m=0.999$ 意味着 key 编码器的时间常数约 1000 步——**比队列长度还慢**，所以队列里横跨几十个 batch 的 key 仍然像由同一个模型产生。这是把「大字典」和「一致性」这两个互相矛盾的要求同时满足的关键。

### 3. 反向传播被截断

梯度**只通过 $\theta_q$ 回传**，不经过队列里的 key。这一点容易被忽略：它意味着动量编码器的作用不只是稳定，还免掉了对 65536 个 key 的反向传播。

## 结论与局限

**贡献**：把对比学习的瓶颈从「显存能放多大 batch」变成「你愿意把队列设多长」，且这个改动是通用的（对任何对比损失都能挂）。它后来成了自监督视觉方法的标准组件。

**局限 / 值得注意的点**：

- **队列里的 key 仍然是过去的表示**，只是过期得慢。MoCo 没有消除陈旧性，只是把半衰期拉长到远超队列长度。这是工程权衡，不是原理解决。
- **$m$ 需要调**。$m=0.9$ 掉点明显，最优区间 0.99–0.9999（p.5）——换数据集 / 换架构时要重新确认这个敏感度。
- **它没有回答增广该怎么设计**。MoCo 的正样本也是同一张图的两个增广，但论文对增广组合的讨论远不如 SimCLR 系统，两篇是互补关系。
- **下游超越要看清对比对象**：AP 超过的是同一检测架构下的 ImageNet 监督预训练，不等于超过所有监督方法。
